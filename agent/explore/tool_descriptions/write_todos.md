Plan the research, and keep the plan current as it changes.

Use it on any question that needs more than one workstream: it is what lets a
long run survive its own summarization, because the plan stays in state while
the conversation behind it is compacted away.

## What a todo is here

One workstream: a question whose answer could change what the wiki concludes,
the evidence that would settle it, and the page its findings go to. Not "search
for field data" but "how does X perform outside the lab -- independent field
studies, not the maker's figures -- extending /{research_dir}/field-performance.md".
If you are the orchestrator, the bookkeeping -- the index, the overview, the open
questions, the log -- is one todo too, so it is not dropped at the end. If you are
a researcher, it is not yours: your todos end at your page.

## How to use it

1. Write the plan before the first delegation, once you know which questions this
   run takes on. The todo list is the *working copy*, held in this session and
   lost with it; what a later reader gets is `open-questions.md` and the log.
2. Mark a workstream `in_progress` when you delegate it and `completed` when its
   page is saved -- not when the sub-agent replies. Keep at least one item
   `in_progress` while work remains.
3. Revise the list as findings come back. A contradiction between two sources,
   or a gap that would change the conclusion, is a new todo; a question that
   turned out not to matter should be deleted rather than quietly dropped.
4. Never mark a workstream complete because its searches ran out. What is still
   unanswered goes into `open-questions.md` -- an open question the next run can
   pick up is worth more than a confident answer nobody can trace.

## What it is not

It is not the deliverable, and neither is your final message. Ignore any
guidance saying the answer must appear as text in your last turn: here the
answer is the file under `/{research_dir}/`, and the reply that ends the run is a
few sentences naming which pages you wrote. Skip this tool entirely for a single
factual question that one sub-agent can answer.
